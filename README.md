# xcpc-server

## 1 前提

你必须安装了 MongoDB，并且运行在 27017 端口

## 2 运行

```sh
npm install   # 安装依赖
npm run dev   # 启动
```

你只要看到

```sh
Server running at http://127.0.0.1:3000
MongoDB 连接成功
```

就是成功了。

## 协会官网登录

普通用户通过协会官网账号或邮箱认证，支持密码和六位邮箱验证码两种方式。
后端只使用官网认证响应的 `numberId` 精确匹配本系统 `studentId`，沿用现有用户、角色和集训数据；
不会按邮箱、用户名或姓名匹配，也不会自动创建队员。官网未绑定学号或系统未录入该学号时拒绝登录。

使用右下角系统账号入口登录 `admin`，在“系统设置 → 数据接入与密钥”配置协会官网登录 appKey。
密钥必须已启用并具有“外部登录”权限，仅由后端发送给 `https://www.cwnupaa.com/api`。
系统管理保存后立即生效，页面只返回是否配置，不回传完整密钥。原 `.env.local` 的 appKey 在升级启动时自动导入，
不会覆盖已在系统管理中保存的新值；环境文件继续兼容首次安装，真实密钥不进入前端或版本包。
保留的本地系统账号仍由后端 `SYSTEM_LOGIN_USERNAMES=admin` 控制。

### 前端接口

- `POST /users/login`：`{ "loginType": "password", "account": "官网账号或邮箱", "credential": "官网密码" }`。
- `POST /users/login`：`{ "loginType": "code", "account": "官网绑定邮箱", "credential": "123456" }`。
- `POST /users/send-code`：`{ "email": "官网绑定邮箱" }`。验证码发送间隔为 60 秒，由官网校验。
- `POST /users/system-login`：`{ "username": "admin", "password": "系统账号密码" }`，供右下角独立入口使用。

登录成功仍返回 `{ success: true, code: 200, message, data: { user, token } }`。
认证失败返回对应的 HTTP 状态码和业务码；官网不可用、配置无效时不会回退到本地密码。
普通队员原有账号/学号配本地密码的登录方式已关闭；系统入口默认仅允许 `admin`，并且仅支持用户名。
`SYSTEM_LOGIN_USERNAMES` 为空时关闭系统登录；如需调整保留账号，用英文逗号分隔用户名。
普通队员应到协会官网修改或重置密码，本系统密码接口只对保留的系统账号生效。

升级后旧登录凭证全部失效，需要重新登录。新凭证区分官网认证与系统账号认证；移除系统账号许可后，
该账号已有的系统登录凭证也会失效。无需更改队员数据库或删除原有密码。

## 协会 OJ 训练与补题

配套前端项目为 `../xcpc-team-manager`，训练中心新建或编辑时选择“协会 OJ”，粘贴比赛链接：

```text
https://oj.cwnupaa.com/contest/6adb59680b835c39ff13486c
```

后端仅访问 `https://oj.cwnupaa.com`，校验比赛链接后读取真实题目 ID 顺序、题数、开始时间和时长。
标题可留空，留空时采用 OJ 比赛标题；达标目标继续按一队、二队配置。创建、编辑保存以及详情页的
“同步协会 OJ 补题情况”都会重新同步。详情页可查看绑定 ID、每题通过状态、原比赛和最近同步时间。

队员需在队员管理中绑定 `ojInfo.cwnuoj` 为协会 OJ 的**数字用户 ID**，不是协会官网账号、学号或 OJ 昵称。
系统对所有在役非 Teacher 队员读取 OJ 公开个人页的完整通过题目列表，与比赛题目 ID 取交集；
Hydro 在比赛和练习提交后均更新此列表，因此包含赛中通过和赛后补题，且重复通过同一道题只计一次。
此统计与比赛信息板一样，表示题目当前是否已通过，不要求通过时间晚于比赛开始。

未绑定或填写非数字 ID 的队员单独标记，不计为达标；读取失败、账号不存在或响应格式异常时，
整次同步失败并保留原有数据，不会将失败误记为零题。当前接入公开可访问的比赛和用户，无需管理员 Cookie。
信息板的游客响应不会按 UID 返回真实通过状态，因此不使用其中的 `accepted: false` 作为队员成绩。

### 时间筛选

`GET /training` 支持可选 `startDate`、`endDate`，按**训练开始时间**筛选，支持仅起始、仅截止、两端及重置。
可同时传入 `type=ASSESSMENT`（考核赛）或 `type=TRAINING`（日常训练），不传或空字符串表示全部类型；非法类型返回 400：

```text
/training?startDate=2026-10-01&endDate=2026-10-31
/training?startDate=2026-10-25T11:00:00.000Z
/training?type=ASSESSMENT&startDate=2026-10-01&endDate=2026-10-31
```

带时区的 ISO 时间精确到指定时刻，包含两端；纯日期按北京时间整天计算，截止日期包含当天全部时间。
非法日期、未带时区的日期时间或起止顺序颠倒返回 400。前端的两个日期时间选择框会转换为带时区的 ISO 时间。

本次改动不需要数据库迁移，旧平台的训练数据继续兼容。上线时需同时更新前端和后端，并把 `.env.local`
中的配置安全地放到运行后端的环境；该文件不会随 Git 同步。

## 协会官网外榜训练

新建或编辑训练时选择“协会官网外榜”，输入 `https://www.cwnupaa.com/contest/board/外榜ID`。
后端调用官网现有公开接口 `GET /api/leaderboard/{boardId}?scope=personal`，读取比赛时间、题目和每题成绩。
外榜 ID 与官网比赛 ID 是不同的标识，必须使用外榜页面的链接。标题可留空，默认采用外榜名称。

官网已有匹配所需接口，无需修改官网代码：公开榜单返回官网 `itemId` / `memberIds` 和 `problemStatus`，
官网远程登录返回 `userId` / `userAccount` / `numberId`。系统先通过已验证的学号定位队员，再保存账号与 ID：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| 用户 `_id` | 本系统的 MongoDB 用户 ID | 集训数据所属队员 |
| `associationIdentity.userId` | 协会官网用户 ID | 关联官网外榜的 `itemId` / `memberIds` |
| `associationIdentity.account` | 认证返回的官网账号 | 账号展示，账号改名后重新登录更新 |
| `ojInfo.cwnuoj` | 学校 OJ（`oj.cwnupaa.com`）数字用户 ID | 学校 OJ 题目与补题统计 |

这些 ID 相互独立，禁止将学校 OJ ID、本系统用户名、姓名或比赛临时账号当作官网用户 ID。
官网身份仅在官网认证成功时自动记录，新增、编辑或批量导入队员不能伪造该绑定。
绑定记录中的学号必须与队员当前学号一致，否则需重新登录认证。升级前已有队员需要退出后使用官网账号
重新登录一次，再在训练详情点击同步。系统信息、队员详情、个人主页均分别显示官网 ID 与学校 OJ ID。

个人赛读取本人记录；团队榜按成员官网 ID 关联，GPLT 团队通过题目取公开个人成绩的通过题目并集；XCPC / LANQIAO 使用整队成绩，
团队通过题目分别记入每位匹配队员的个人训练题数，按其所属一队 / 二队目标计算达标。页面标明“团队成绩计入个人”。
AC 记为通过；计分题仅在取得有效满分时记为通过，部分分仍展示得分。使用外榜原始题号，保留原赛制的成绩选择规则。

遵守外榜开放和封榜状态，不使用管理员或滚榜接口解封。未绑定、外榜无记录、重复绑定各有明确状态；
未解封时仅同步公开成绩并提示“待解封”。上游失败、响应不完整或无法识别关联信息时保留原快照。
外榜只反映官网已收集的比赛成绩，不代表学校 OJ 的赛后补题进度；后者继续使用“协会 OJ”数据来源。

## 队员实时筛选

`GET /users` 支持 `account`，按学号或系统账号做包含匹配，并可与姓名、学院、年级、性别、状态、角色、队伍组合。
原有 `username`、`studentId` 参数继续精确匹配。文本包含匹配会转义正则字符，按输入文字检索。
前端文本输入停止 300 毫秒后查询、下拉条件立即查询，筛选改变回到第一页；旧请求不会覆盖新条件的结果。
查无匹配或请求失败只改变结果和提示，保留筛选框内容；重置筛选保留当前每页条数。

## 批量修改状态与队伍

管理员使用 `PUT /users/batch/membership`，提供 `userIds`（表格勾选）或 `studentIds`（一行一个学号解析后的数组），两者互斥。
可选 `status: Active|Retired`、`trainingTeam: First|Second`，至少选择一项；未提供的字段保持不变。
每次最多 1000 个标识，学号精确匹配并保留前导零，重复项自动去重。系统与教师账号不参与修改。
响应返回请求数、匹配数、实际更新数、原本已为目标状态的人数，以及未找到、受保护的标识。
无匹配不算修改成功，界面保留粘贴内容和结果明细。批量直接调整状态不代替退队申请的审批记录。

## 官网认证荣誉与精简控制台

个人奖项、队员荣誉和控制台荣誉统一通过 `GET /users/:id/association-honors` 读取。
后端只使用该队员认证绑定的官网用户 ID 请求 `https://www.cwnupaa.com/api/certificate/honor-wall?userId=...`。
官网荣誉墙返回已审核证书认定和有效的官网颁发记录，包含赛事名称、级别、奖项和日期，支持团队证书；
不从本地比赛记录或工单拼装个人奖项。未绑定时提示重新使用官网账号登录，读取失败显示错误，不伪装为空记录。

喜报中心、公告中心、比赛管理、手动赛事管理及其旧接口已下线；旧前端地址重定向到控制台或官网荣誉页。
历史数据保留，不删除原有记录或改写历史 Rating。控制台改为队员概况、训练计划、刷题总量与本人官网认证荣誉。

## 每场训练的出题人

训练创建、编辑接口支持 `problemSetterIds`（本系统用户 `_id` 数组），可选多人、去重，最多 1000 人。
只允许已有的非系统账号；不按姓名自动认领。管理权限与编辑训练一致，队员搜索接口为
`GET /training/problem-setter-options?keyword=姓名或学号或账号`，每次最多返回 50 项，只返回必要展示字段。

列表、详情、创建、编辑、刷新和导入的响应统一附带 `problemSetterIds`、`problemSetters`。
出题人在该场的成绩视图中标记 `isProblemSetter: true`，全部题目视为完成并达标，即使未绑定外部 OJ 或没有参赛记录。
该默认完成状态只由后端根据出题人名单生成，不覆盖数据库保存的真实同步 / 导入成绩；取消出题人后恢复实际记录。
刷新、导入或更换数据来源不会清空出题人名单；修改比赛总题数后默认完成题数随之变化。

## 学期管理与官网同步

系统设置新增学期管理，学期名称采用 `YYYY-YYYY-1/2`（连续学年），只设置开始日期。
每个学期从北京时间开始日 00:00 起，到下一学期开始前为止；最新学期没有截止时间，包含寒暑假。
不同学期不能使用同一个开始日期；已创建的名称不可手动改名。旧目录里的结束日期不再参与归属或同步。
本功能与 Rating 赛季独立，保存学期不会触发赛季结算或清零。

- `GET /config/terms`：登录用户读取学期目录和最近同步时间。
- `POST /config/terms`、`PUT /config/terms/:id`：训练管理员添加、编辑学期。
- `POST /config/terms/sync`：从官网公开的 `https://www.cwnupaa.com/api/common/terms` 同步完整学期目录。

目录保存在全局设置 `TRAINING_TERMS` 中。官网 ID 记录于 `websiteTermId`，本系统使用稳定的 `_id` 关联训练。
同步先校验全部数据，再按官网 ID / 同名学期合并，保留本地新增和官网不再返回的记录，不删除关联；失败不覆盖原目录。
整个目录一次写入，并通过版本检查避免并发同步相互覆盖。官网来源学期的手动开始日期修改会在再次同步时采用官网日期。

新训练必须选择 `termId`（本系统学期 `_id`），表示所属**计分学期**；允许在本学期举办、计入上学期。
编辑未指定学期的旧训练时也须明确选择。旧训练在编辑前仍按举办时间和新学期边界匹配，无需强制改写历史。
列表与详情返回 `resolvedTermId`、`termName`、`termAssignment`；`eventTermName` 单独表示实际举办学期。
`GET /training?termId=学期ID` 将手动归属及自动日期匹配的记录一起筛选，`termId=unassigned` 筛选未归属记录；
可同时使用 `type`、`startDate`、`endDate`，各条件取交集。所选计分学期在刷新、导入或调整实际举办时间后保留。

首次发布后在生产配置所在目录运行 `node dist/scripts/sync-association-terms.js` 可实际导入官网学期；
开发环境也提供 `npm run sync:association-terms`。该命令会写入当前配置的数据库，不能当作测试命令使用。

## 学校 OJ CP Tracker

参照官网 `CrawlerLocalRunner.crawlCwnu`，通过固定域名下的 `/api/submissions/{UID}` 和 `/api/stats/{UID}`
获取学校 OJ 已通过题目及总数，仅使用 `ojInfo.cwnuoj` 的数字 UID，与官网 ID 分开。
逐题记录按学校 OJ 稳定的数字 `pid` 去重，保留自定义题号用于展示和搜索，采用最早 AC 的 `judgeAt`；题目难度依官网 Hydro 0–10 映射标准化。
题目元数据缓存于 `data/cwnuoj-difficulty.json`，读取难度失败显示 N/A 或保留已知难度，不编造通过日期。
接口失败、UID 不一致、结果不完整或声明的记录总数不匹配时不覆盖已有数据。

`POST /submissions/cwnuoj` 供登录用户同步自己的绑定账号，后台完成后通知；CP Tracker 的来源筛选、
同步选项、热力图、趋势图和难度分布均包含 `CWNUOJ`。每天北京时间 00:00 自动同步已绑定队员；
服务启动后后台补齐尚未同步或已过期的账号，同一用户的并发请求合并。学校 OJ 总题数继续参与原有每日全队统计。
记录包含 `sourceAccount`，账号改绑后按当前 UID 展示，避免将旧账号记录混为当前账号成绩。

## VP System 训练历史

训练来源选择 `VP_SYSTEM`，填写 `vpContestUrl` 原站比赛 URL，并选择计分学期及举办时间。
后端按队员认证绑定的官网 ID 调用 `https://vp.cwnupaa.com/api/external/vp-history`，使用 `limit=1` 读取
各自最近一次已结束 VP；不通过邮箱、姓名或学号猜测身份，不导入 live / 独立补题 / 尚未结束的记录。
同一条团队历史分别记入每个匹配成员的个人训练统计，不跨成员去重；保留团队来源及原榜排名（含非数字排名）。
分钟制罚时和每题时间转换为秒。默认只用赛中通过判定达标，`vpIncludePractice=true` 可同时计入赛后补题，
两部分仍分别展示。取题目列表及每题结果校验成功后才保存，读取失败、无可导入记录或达到 API 限流均保留原有快照。

密钥在“系统设置 → 数据接入与密钥”中保存 VP System 生成的历史只读 API Key。
`GET /config/integration-keys` 只返回配置状态；管理员 `POST /config/integration-keys` 使用
`{ service: 'association' | 'vp-history', apiKey: '...' }` 更新对应密钥。AtCoder Cookie 同页管理，只返回是否配置。
未配置 VP 密钥时显示提示，其他功能正常；配置后即可创建、编辑和刷新 VP 训练。密钥不会写入训练或传给前端。

## 登录界面与会话缓存

API 响应统一使用 `Cache-Control: no-store, private` 并按 Authorization 区分。前端在登录、退出、过期、
跨标签页切换身份及浏览器历史缓存恢复时重建页面，旧会话请求不再覆盖当前用户资料或通知。
静态站点的 HTML 入口使用不缓存策略，避免重新进入管理系统时继续引用旧版入口文件。
